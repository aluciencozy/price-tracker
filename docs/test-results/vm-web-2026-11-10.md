## Findings

### F1 — Static web responses lacked HSTS and CSP — RESOLVED LIVE

The initial November 10 (project-local) check found no HSTS or CSP on the HTML
response. A read-only follow-up on November 11, 2026 UTC (November 10 project-local)
confirmed one value each for HSTS, CSP, referrer policy, nosniff, and X-frame
policy on `/`, `/register`, `/verify-email`, `/api/ready`, and `/api/tracked-items`.
HSTS is `max-age=86400`; CSP is the deployed same-origin policy, including
`frame-ancestors 'none'`, `connect-src 'self'`, and `upgrade-insecure-requests`.
The API tracking request returned 401 without credentials, as expected. The parent
made the Apache change; this audit made no deployment/configuration changes.

### F2 — Signed-out private-view fallback had no H1 — RESOLVED LOCALLY, NOT DEPLOYED

The live screens still lack the H1 until the application change is deployed. In the
local production build, only the signed-out `PrivateView` fallback now renders the
existing “Sign in to continue” title as an H1; its 14px styling preserves the
existing status-title appearance at mobile and desktop widths. The shared `Status`
component and other empty/error states were not changed. axe-core 4.12.1 reported
zero violations on both local routes (34 checks each) at `/watchlist` and `/account`.
The local browser used a test-only anonymous 401 response for `GET /api/auth/web/me`
on `127.0.0.1:4179`; it created no session and made no private-data request.

### F3 — API security headers were duplicated/conflicting — RESOLVED LIVE

The initial API responses contained duplicate referrer/nosniff headers and both
`X-Frame-Options: DENY` and `SAMEORIGIN`. The November 11 UTC follow-up found only
one value for each checked security header on the API responses listed under F1.

## Live browser and local-build follow-up

The November 11, 2026 UTC browser pass (November 10 project-local date) loaded the
current live home, register, login, forgot, verify-email, reset-password, watchlist,
and account routes at 390×844 and 1440×900. Same-origin JavaScript and CSS assets
returned 200; account forms rendered without sample UI, no horizontal overflow was
observed, and no CSP console/runtime errors were recorded. No form was submitted;
the signed-out `/me` 401 responses were expected. The live app has the parent’s
updated Apache headers, but does **not** yet include the local H1 change.

After the live pass, the API-mode web production build was rendered locally at
390×844 and 1440×900. Both signed-out private routes had a semantic H1, zero axe
violations, and no horizontal overflow. These local results do not claim that the
application fix has been deployed.
